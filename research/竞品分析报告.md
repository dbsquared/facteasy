## 一、执行摘要（关键结论）

1. **市场空白明确存在**：FactEasy 的核心定位——「对病毒式传播的视频/Vlog/播客做**逐条**事实核查 + **秒级时间戳片段锚点** + **回填原视频评论区直达链接**」——目前没有任何一款成熟产品打通这三件事。
   - 文章级核查（Snopes / PolitiFact / 腾讯较真）只产出整篇结论，无法锚定视频里的"某一秒说了什么"。
   - 监测/抽取工具（Full Fact / Logically）停在"发现可疑视频 + 转写 + 抽 claim + 告警"，不构成面向公众的逐条核查页。
   - 平台侧机制（X Community Notes / YouTube Notes / 抖音辟谣 / B站争议标）只能在**整条视频**上加注释或标签，不能逐条、不能带秒级锚点、不能外链回填。
2. **最直接的可比对手是"AI 驱动查证"类工具**（腾讯较真AI、加拿大的 GetFact/Laura、美国的 Gigafact），但它们均为「文本/链接输入 → 结论输出」形态，**没有视频逐条抽取 + 片段锚点 + 回评**这一组合。
3. **风险高度集中在"抓取/下载 + 跨平台评论发布"**：YouTube 下载受 ToS 限制、TikTok/抖音/B站有反爬与自动化风控、X/Twitter API 已收费且收紧、各平台对"自动化评论/外链"普遍限制。这是 FactEasy 落地最大的工程与合规不确定性。
4. **市场教育已被部分完成**：Logically 在印度 2024 大选中发现超 50% 需核查内容为视频；腾讯较真AI（2025-08 上线）用"结论—过程—评估 + 可信度评分"验证了用户对"AI 查证"的接受度。FactEasy 不必从零教育市场，但需做出**颗粒度（逐条/秒级）**上的代差。

### 2.4 中文市场专项（最需注意"平台自建 + 国家队"双重挤压）

- **腾讯较真 / 较真AI（2025-08 上线）**：**与 FactEasy 最具可比性**。基于腾讯新闻 10 年查证经验 + 百万级辟谣数据库，由**腾讯混元大模型**支持；交互为"输入框问问题 → 结论—过程—评估 + 可信度评分（如 10/10）"。但**形态是文本对话/链接查证，不做视频逐条抽取与片段锚点**，也不回填原视频评论。**（关键空白）**
- **百度"权威发布"**：数字人/AI 互动/智能体做辟谣传播。
- **抖音"热点辟谣"/"AI求真"**：如前，平台内闭环。
- **中国互联网联合辟谣平台（piyao.org.cn）**：接收线索、查证、曝光，矩阵覆盖微博/微信/抖音。

> **中外差异小结**：国际市场以"独立第三方核查机构 + ClaimReview 标准 + 平台信息面板"为主，工具链较开放；中国市场则是"平台自建辟谣（抖音AI求真、B站专区）+ 国家队（联合辟谣平台）"主导，**第三方独立视频核查工具的生存空间更依赖"平台未覆盖的颗粒度（逐条/秒级）"与"公信力背书（对接权威源）"**。

## 四、差异化空白机会

### 4.1 空白定位
FactEasy 的差异化不在于"做事实核查"（已有大量玩家），而在于**把核查的颗粒度推进到"视频里的某一秒说的某一句话"，并把它送回用户正在看的原视频场景里**。这是当前市场的三重断裂：

- **断裂 A（文章级 ↔ 视频级）**：传统核查产出整篇结论，用户回到视频仍找不到"哪句话是假的"。
- **断裂 B（发现 ↔ 呈现）**：Full Fact / Logically 能"发现并抽取"，但呈现仍服务于机构内部，不面向公众做逐条可点查的核查页。
- **断裂 C（独立核查 ↔ 原场景）**：平台侧 Notes/辟谣标签只能加在整条视频上，且绝不外链；第三方工具又普遍卡在"无法自动化回填评论"。

### 4.2 SWOT 式归纳

**S（优势/机会点）**
- 组合创新：逐条 + 秒级锚点 + 回评，形成"可点查、可溯源、可回到现场"的独特体验。
- 强引用性：每条核查都带原始时间戳与片段，天然适合 ClaimReview 结构化与 SEO/平台展示。
- 市场已被教育：较真AI、GetFact、Logically 验证了"AI 查证"需求与接受度。

**W（劣势/软肋）**
- 工程与合规重：多平台抓取/下载/转写/评论回填，任一环节都依赖外部平台政策。
- 内容版权与再传播风险：视频片段二次传播、CC 协议、各地不实信息治理法规。
- 公信力从零建立：相比国家队/老牌机构，独立产品的可信度需靠"多源证据 + 透明方法"补。

**O（机会）**
- 视频 misinformation 占比持续上升（Logically：印度大选 >50% 为视频类）。
- 平台自建辟谣（抖音AI求真、YouTube Notes）只做"整条"，**反而凸显 FactEasy 的"逐条/秒级"代差价值**。
- 可对接权威源（中国互联网联合辟谣平台、Google Fact Check API、ClaimReview）提升公信力与覆盖面。

**T（威胁）**
- 平台闭环挤压：抖音/腾讯/字节系对"外部工具抓取 + 自动评论/外链"极度敏感，外层工具易被限流或封禁。
- 政策收紧：Meta 2025 退出美区第三方 fact-check（转向 Community Notes 模式）；X API 收费；YouTube 下载受 ToS 限制。
- 若大平台将"逐条锚点式核查"纳入自身（如 YouTube Notes 未来支持时间戳锚点），空白会被快速填平。

## 五、可行性 / 风险提醒（需提前规避）

| 风险点 | 现状 | 对 FactEasy 的影响 | 规避建议 |
|---|---|---|---|
| **视频下载权** | YouTube ToS 限制下载；TikTok/抖音/B站有反爬与风控；部分平台仅授权特定合作方 | 流水线第 1–2 步（下载→转写）可能受阻或被封 | 优先用**平台官方/半官方接口**（YT 字幕 API、已授权抓取）；对无接口平台采用"用户自传文件/授权链接"模式；转写优先用 YT 原生字幕时间轴 |
| **ASR 准确性/Hallucination** | Whisper 自托管免费但连续虚构率偏高；商业 API 更准但按量计费 | 秒级锚点依赖准确时间轴；幻觉会污染"逐条" | 采用商业 ASR（AssemblyAI/Deepgram）或 Whisper + 校验；保留人工/用户纠偏 |
| **跨平台评论发布（回填）** | YouTube/TikTok/抖音/B站对自动化评论、外链、营销内容普遍限制，且判 spam 风险高 | FactEasy 第 4 步"回填评论区"是最高风险项 | **不宜默认全自动**；改为"生成可复制的直达链接/卡片，引导人工发布"，或申请平台合作/白名单；作为 P1/P2 灰度 |
| **反爬 / 风控** | IP 封禁、验证码、账号风控 | 策展与回填稳定性 | 限速、代理策略、合规 UA；优先官方 API |
| **版权与合规** | 视频片段再传播、CC 协议、各地"网络谣言/不实信息"治理法规（含中国清朗专项行动） | 法律与下架风险 | 片段仅作"引用/锚点"（短时长、指向原视频）；对接权威辟谣源以增公信；建立申诉/更正机制 |
| **数据标准对接** | ClaimReview 已成事实标准；Google Fact Check API 免费 | 不接入则重复造轮子、且难被搜索引擎/平台展示 | **必做 ClaimReview 导出 + 可选对接 Google Fact Check API**；中文侧考虑对接中国互联网联合辟谣平台线索 |

## 六、对 PRD 的关键建议

### P0（差异化必做，构成 FactEasy 核心价值）
1. **视频策展 + 多平台接入**：YouTube、Bilibili、TikTok、抖音，至少支持链接提交 + 授权的原生字幕/转写获取。
2. **自动转写 + 逐条抽取**：把内容拆成"陈述 / 论点 / 观点 / 声称事实 / 新闻条目"，每条带文本。
3. **秒级时间戳 + 片段播放链接（锚点）**：这是与所有竞品的代差点，**优先于花哨 UI**。
4. **LLM 分析笔记**：逐条产出"事实核查结论 / 参考资料 / 信息来源 / 摘要 / 影响 / 背景"。
5. **发布到自有网站 + ClaimReview 结构化导出**：让核查页可被搜索引擎与平台发现，沉淀资产。

### P1（增强差异化 / 提升可信）
6. **多语种**：至少中英，呼应 Logically/Full Fact 的多语能力。
7. **可信度评分**：参考腾讯较真AI 的"结论—过程—评估 + 信心指数"，提升用户信任。
8. **平台辟谣标签/权威源联动**：对接中国互联网联合辟谣平台线索、Google Fact Check API，避免重复造轮子并增公信。

### 宜回避 / 后置（高风险或低 ROI）
- **直接自动回填原视频评论区** → 改为"生成可复制直达链接/卡片，引导用户或运营人工发布"，待平台合作/白名单后再自动化（P1/P2 灰度）。**这是最大的合规雷区，不要在 Beta 默认开启。**
- **自建海量核查数据库** → 优先接入 ClaimReview / Google Fact Check API / 权威辟谣源，把精力放在"视频逐条 + 锚点"的独有层。
- **追逐"全平台全自动抓取"** → 先聚焦 1–2 个政策友好、易获取字幕的平台（建议 YouTube + Bilibili）跑通 MVP，再扩展。
